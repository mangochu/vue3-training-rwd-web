# 00. 專案總覽

## 目標

動手寫程式之前，先想清楚**要做什麼、不做什麼**。很多練習專案沒做完，原因都是範圍一直變大。

---

## 1. 網站內容規劃

先把要放的內容寫下來。內容決定版面，不要倒過來。

### 必做（MVP）

| 區塊 | 內容 | 練習重點 |
| --- | --- | --- |
| Header | Logo / 名字、導覽列（About、Projects、Resume、Contact） | 固定頂部、手機漢堡選單 |
| Hero | 名字、一句話介紹、CTA 按鈕（看作品 / 下載履歷） | 大字級的 RWD、置中排版 |
| About | 大頭照、自我介紹、技能標籤 | 圖文左右排列 → 手機改成上下排列 |
| Projects | 作品卡片列表，可依技術標籤篩選 | CSS Grid、`v-for`、`computed` 篩選 |
| Resume | 工作 / 學歷時間軸、下載 PDF 履歷 | 時間軸版面、資料驅動畫面 |
| Contact | Email、GitHub、LinkedIn 等連結 | icon、`target="_blank"` 安全性 |
| Footer | 版權、社群連結 | 簡單的 Flex |

### 第二階段

- 作品詳細頁 `/projects/:slug`
- 404 頁面
- 深色模式切換
- 捲動進場動畫

### 不做（避免範圍變大）

- 後端、資料庫、登入
- CMS 後台
- 部落格系統（之後可以另外開專案）

> **任務**：複製上面的表格，改成**你自己的**內容，至少準備 3 個作品（就算是練習作品也可以）、
> 1 段自我介紹、你的 GitHub 網址。寫在一個 `content-draft.md` 草稿裡，第 03 章會用到。

## 2. 技術選型與理由

| 技術 | 用途 | 為什麼選它 |
| --- | --- | --- |
| **pnpm** | 套件管理 | 安裝快、省硬碟空間、依賴管理比較嚴格（不會讓你不小心用到沒宣告的套件） |
| **Vite** | 開發伺服器與打包 | Vue 官方推薦，啟動和熱更新都很快 |
| **Vue 3 `<script setup>`** | UI 框架 | 現在 Vue 的主流寫法，搭配 TS 時最好推導型別 |
| **TypeScript** | 型別系統 | 資料（作品、履歷）的格式由型別保護，打錯欄位編輯器會直接提示 |
| **Vue Router** | 路由 | 作品詳細頁、404 頁需要它 |
| **原生 CSS（CSS 變數）** | 樣式 | **刻意不用 UI 框架**，目的是練 RWD 基本功 |
| **ESLint + Prettier** | 程式碼品質 / 格式 | 業界標配 |
| **Vitest** | 單元測試 | 和 Vite 共用設定，上手門檻低 |
| **GitHub Actions + Pages** | CI/CD 與部署 | 免費、和 repo 整合在一起 |

### 為什麼不用 Tailwind / Element Plus / Vuetify？

這個專案的目的之一是**練 RWD 與 UI 佈局**。UI 框架把 Grid、斷點、元件都包好了，你就練不到：

- Flexbox 和 Grid 什麼時候用哪個
- Mobile First 的 media query 怎麼寫
- 漢堡選單的開關邏輯與無障礙屬性

等這個專案做完、基本功熟了，下一個專案再試 Tailwind，你會更清楚它幫你省了哪些事。

## 3. 開發流程總覽

```
設計（01）→ 初始化（02）→ 結構（03）→ 版面（04）→ 元件（05）→ 路由（06）
                                    ↑                              ↓
                                    └──── 每完成一個功能就 commit ──┘
                                                                   ↓
                                    品質檢查（07）→ CI/CD 上線（08）→ 進階（09）
```

**建議**：不要等全部做完才部署。做完第 04 章（版面）時，就可以先跳去做第 08 章的部署，
之後每次 push 都會自動更新網站，看到成果會比較有動力。
